# Security

Do not post credentials, private logs, or personal preferences in issues. Use GitHub’s private vulnerability reporting for sensitive reports when available; otherwise open a minimal issue asking for a private contact without disclosing the vulnerability details.

Accessibility permits broad UI control. Loki limits its own discovery to menu-extra trees and user-selected activation. Report any path that reaches unrelated document content or clicks outside the validated menu-bar bounds.

Release artifacts should be Developer ID signed and notarized, with SHA-256 checksums. A source build is ad-hoc signed unless the builder supplies a signing identity. Preview releases are not a security or compatibility guarantee.
